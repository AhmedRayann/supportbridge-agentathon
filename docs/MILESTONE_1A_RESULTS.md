## Resolved setup issues and remaining limits

- PowerShell blocks `npm.ps1`; using `npm.cmd` works without changing execution policy.
- Default `py`/`python` Windows aliases were inaccessible; the installed Python
  3.13 executable worked. README describes substituting an absolute executable.
- Initial npm cache access and pip network requests hit sandbox restrictions;
  elevated retries succeeded.
- Initial Ruff import ordering and ESLint anonymous-export findings were fixed.
  Replacing the deprecated Starlette TestClient/httpx combination with async
  HTTPX ASGI transport removed the initial pytest deprecation warning.
- npm installation reports an upstream ESLint 9 support/deprecation notice.
  The installed lint setup passes and npm's installation audit reports zero
  vulnerabilities. This notice does not block 1A.
- Git reports ownership mismatch under the execution account. Read-only Git
  checks used a per-command `safe.directory` setting; no global Git configuration
  was changed.
- No Vercel CLI, CLI authentication file or `VERCEL_TOKEN` was available. No cloud
  deployment was attempted without access. The official current starter and
  routing/runtime guidance were checked; README links those sources. Services
  routing, account behavior and the two-project fallback remain unverified in
  Vercel Production. Follow the README deployment instructions and record the
  stable production URL plus incognito Network/UI results to close the gate.
- No provider compatibility, database or checkout tests apply in 1A. No checkout,
  LangGraph, AI clients, persistence or elaborate UI has been implemented.
